# Tavily Retrieval Methodology for Benchmark Evidence Collection

## Scope

This document describes the retained Tavily-based retrieval workflow used to
construct benchmark evidence artifacts from the 2,000-query candidate pool. It
is a methodology record for query-time web retrieval, readable-text extraction,
query-focused windowing, filtering, caching, and audit. It is not a claim that
Tavily itself is the source of the benchmark questions or that a later rerun
will reproduce the same web results.

**Scope boundary:** This protocol applies to the benchmark's non-refusal query
route. The current 128 held-out refusal examples come from the TRUST-ALIGN
refusal holdout; they are not Tavily-retrieved benchmark candidates and are
documented separately in the benchmark dataset card.

The implementation is `scripts/retrieve_conflicts_benchmark_docs.py`; the
candidate input is generated by `scripts/build_conflicts_benchmark_candidates.py`.
The dataset-level context and retained outputs are described in
[`BENCHMARK_DATASET_DESCRIPTION.md`](BENCHMARK_DATASET_DESCRIPTION.md).

## Retained run and inputs

The retained run starts with `data/benchmark_build/candidates/query_pool_2000.jsonl`
(2,000 deduplicated, source-balanced queries). It used Tavily search with 20
requested results per query and retained up to 10 evidence documents. The
principal raw output is:

```text
data/benchmark_build/retrieved/
  full2000_fresh_tavily_20_keep10_tasb_readable_raw_with_fulltext.jsonl
```

The run record reports 2,000 Tavily requests and no search-cache hits at initial
collection. API keys are read from `TAVILY_API_KEY` or the comma-separated
`TAVILY_API_KEYS` environment variable; they are never committed. Each record
stores search/provider metadata but no secret credential.

## Retrieval procedure

For every query, the script performs the following sequence.

1. **Search.** It sends a `POST` request to Tavily's `/search` endpoint with
   `search_depth="basic"`, `topic="general"`, `include_answer=false`,
   `include_images=false`, `include_usage=true`, raw content set to `text`
   unless full-text fetching is skipped, and `max_results` equal to the search
   result target. The retained setting requests 20 results.
2. **Retry and key rotation.** A 60-second HTTP client timeout is used. The
   script rotates available Tavily keys between retry attempts and retries
   authentication, quota, and rate-limit responses (401, 402, 403, 429), with
   a maximum determined by the configured retry count (at least three or twice
   the number of keys). A 0.7-second post-search delay is the default pacing.
3. **URL-level deduplication and filtering.** Repeated URLs are collapsed.
   Configurable domain exclusions, a minimum selected-window word threshold,
   and a blocked/low-signal detector are applied. The retained exact-ten
   artifact records `drop_blocked=true` and `min_window_words=0`.
4. **Fetch and extract.** For each retained result, the script fetches the page
   (20-second default), follows redirects, and uses `cloudscraper` when
   available, otherwise `httpx`, with a specified browser-like User-Agent.
   HTML is cached per URL. Readable text is extracted with `jusText` using its
   English stoplist; a conservative HTML parser removes scripts, styles,
   `noscript`, and SVG content if `jusText` cannot yield usable text.
5. **Select a query-focused evidence window.** The default selector is TAS-B:
   `sebastian-hofstaetter/distilbert-dot-tas_b-b256-msmarco`. The query and
   document windows are encoded with the model; each document is split into
   512-token windows (510 content tokens after special-token reservation) with
   stride 256, and the highest query/window dot product is selected. Batching
   uses 16 windows. A lexical selector exists as an explicit fallback mode, not
   as a silent replacement for TAS-B.
6. **Emit provenance-rich document fields.** Output includes a stable document
   ID, title, selected snippet, URL, date, original search rank, provider
   score, fetch status, full-text character count, window score, and fallback
   reason where applicable. If the selected text is boilerplate, the script can
   revert to the search snippet rather than preserve unusable page content.

The raw full-text field (`response_str`) is retained when available for audit;
the release dataset deliberately reduces documents to the compact canonical
fields needed for evaluation.

## Cache design and reproducibility boundary

Tavily search responses are cached at:

```text
data/benchmark_build/retrieval_cache/tavily_search/<sha1(query)[:16]>.json
```

Fetched pages and fetch metadata are cached by SHA-1 of URL under
`data/benchmark_build/retrieval_cache/pages/`. Cache entries preserve such
details as request/usage identifiers and statuses where available. The cache
prevents needless re-querying during a resumable run, but it is not a permanent
guarantee of web reproducibility.

Search results and web pages are time-dependent. Ranking, index coverage,
access controls, page content, redirects, and source availability can change.
Consequently, a new call with the same query, parameters, and model may not
match the retained artifact. Reproduction of the *released dataset* should use
the committed JSONL artifacts. Re-running retrieval should be described as a
fresh collection run and compared against the retained snapshot, not presented
as bit-for-bit recovery of historic web evidence.

## Result counts and quality audit

The 2,000-query raw retained run has:

| Retrieval outcome | Queries |
|---|---:|
| Exactly 10 retained documents | 1,878 |
| Fewer than 10 retained documents | 122 |
| Zero retained documents | 118 |
| One retained document | 1 |
| Three retained documents | 2 |
| Seven retained documents | 1 |

The exact-ten subset is `full2000_fresh_annotation_candidates_exact10.jsonl`.
It excludes underfilled records before the reduced evidence set is created.
The raw run has average selected snippet length 267.2 words (5th percentile 14,
median 360, 95th percentile 427). Average available full text is 19,960
characters; 2,582 result documents lack usable full text. The observed fetch
record includes 13,051 results with provider-supplied raw content, 3,454 fetched
pages, 1,824 HTTP 403 responses, 81 HTTP 400 responses, 34 HTTP 404 responses,
and smaller counts of other statuses. These are evidence-collection diagnostics,
not quality labels by themselves.

The manual audit in
`data/benchmark_build/audits/full2000_fresh_manual100_conflict_quality_audit.md`
stratifies 100 exact-ten queries across ConflictingQA (25), FreshQA (25),
SituatedQA temporal (20), SituatedQA geographic (20), and QACC (10). Reviewers
assessed 1,000 selected snippets. Eighty-eight queries were usable, 82 received
high or medium-high confidence, and 12 were rejected as low quality. The most
important recurring issue was geographically underspecified queries paired with
the wrong locale. This motivated strict downstream filtering rather than
treating successful HTTP retrieval as sufficient evidence quality.

Tavily is a broad acquisition stage, not the final benchmark-selection step:
2,000 sourced non-refusal candidates were retrieved; 1,878 exact-ten records
progressed to strict downstream evidence preparation; and the final 736-record
holdout was quality-selected later from the 1,454-record consolidated
human-preselection population. These stages answer distinct questions: whether
enough evidence was retained, whether it was suitable for review, and whether
the item meets the final benchmark-quality criteria.

## Deterministic five-document review set

Human preselection and later annotation use a compact evidence view built from
the exact-ten candidate file:

```bash
python3 scripts/build_benchmark_doc_subset.py
```

For each record, the script divides original ranks into top (1–5) and bottom
(6–10) groups, deterministically selects two top and three bottom documents,
then restores original rank order. The selected document identity is ordered by
a SHA-256 key over seed 62002, record ID, bucket, document ID, and original
rank. The output retains `_original_doc_id`, `_original_search_rank`, and
selection metadata, allowing an auditor to reconstruct which original result
positions were shown. The output is:

```text
data/benchmark_build/retrieved/
  full2000_fresh_annotation_candidates_5docs_2top5_3bottom5_seed62002.jsonl
```

This is not a reranker that claims lower-ranked evidence is stronger; it is a
fixed, auditable sampling design that gives reviewers exposure beyond the first
five search results while constraining cognitive load.

## Running a new Tavily collection

The following creates a new, parameter-matched collection; it does not recreate
the historic web snapshot exactly.

```bash
export TAVILY_API_KEY=...
python3 scripts/retrieve_conflicts_benchmark_docs.py \
  --input data/benchmark_build/candidates/query_pool_2000.jsonl \
  --output data/benchmark_build/retrieved/benchmark2000_retrieved.jsonl \
  --search-provider tavily \
  --top-k 10 \
  --search-max-results 20 \
  --drop-blocked \
  --min-window-words 0 \
  --window-selector tasb
```

Use `--resume` when continuing an interrupted job (it is enabled by default).
For a stricter production-quality threshold, set a positive `--min-window-words`
value, but record that parameter because it changes the retained-document
population. Google Custom Search and DuckDuckGo HTML are supported alternative
providers; they should be treated as distinct retrieval conditions, not mixed
with Tavily results without recording provenance.

## Limitations

- A search rank or TAS-B score measures retrieval relation, not factual truth.
- `jusText` and fallback extraction can fail on dynamic pages, consent walls,
  PDFs, malformed HTML, or anti-bot pages; fetch status must be retained.
- The procedure uses only retrieved evidence. It cannot establish whether an
  omitted authoritative source would change the answer.
- Selected snippets are short, query-focused windows. They may omit qualifying
  context from a source page; this is why evidence quality is reviewed later.
- API and page access change over time. The committed retrieval artifacts are
  the appropriate audit object for the historical benchmark build.
